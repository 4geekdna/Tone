Tone Automations

Grok bots that keep the Tone design → deploy loop consistent

How they fit together
You build with Prompt Builder → Grok deploys to GitHub → Tone Repo Watcher reviews the push → Weekly Health Check audits the catalog → Deploy Prompt Pack hands you next week’s starter prompt.

Tone Repo Watcher Live

Trigger · GitHub push to main on 4geekdna/Tone

Runs after every deploy. Summarizes what changed, flags missing index updates, and calls out generic filenames.

  • Incomplete deploy detection (new HTML without index card)
  • Naming cleanup suggestions (kebab-case, domain prefixes)
  • One-line status: complete / needs index / rename recommended

Weekly Tone Health Check Live

Schedule · Sundays 10:00 America/Los_Angeles

Weekly maintenance brief for the repo and Master Index.

  • Repo tree vs index card comparison
  • Orphan files and dead links
  • Remaining generic names with rename list
  • Prioritized cleanup (max 5 items)

Deploy Prompt Pack Live

Schedule · Mondays 09:00 America/Los_Angeles

Ready-to-paste starter for the next Tone app, aligned with house rules.

  • Lists recent apps for consistency
  • Restates core requirements + filename rules
  • Outputs a Prompt Builder–shaped prompt to copy into chat

House rules these bots enforce

  • Single self-contained HTML, dark mobile-first UI
  • localStorage persistence; reuse Gemini/Places keys when needed
  • Always update index.html with card + version bump
  • Descriptive kebab-case only — never test01 / app1 style names
  • Prefer prefixes: gps-, chakra-, health-, ai-, tool-

Managed in Grok → Automations. Notifications: app + email.
